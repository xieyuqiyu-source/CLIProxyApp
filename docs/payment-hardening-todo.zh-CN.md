# 支付流程优化 TODO

更新时间：2026-04-08

目标：
- 强化 `CPAPP + CLIProxyCloud` 的会员购买流程
- 降低重复下单、误操作、状态不同步、支付成功无反馈等问题
- 分阶段上线，随时提交并同步远端，最终由人工审核确认

## Phase 1：支付流程防呆

- [ ] 同一用户同一套餐存在 `pending` 订单时，优先复用旧订单，避免重复创建。
- [ ] 在支付弹窗中显示订单有效期倒计时；过期后自动切换为“重新创建订单”状态。
- [ ] 新增“我已支付，立即校验”按钮，供用户手动触发一次查单。
- [ ] 关闭支付弹窗前，如果存在待支付订单，弹出二次确认。
- [ ] 订单失效、关闭、失败时，二维码区域切换为明确的失败/失效状态，不再继续展示旧二维码。

## Phase 2：支付状态与幂等

- [ ] 支付中锁定套餐和支付方式，避免用户误以为正在支付 A，后台又创建了 B。
- [ ] 后端进一步审查支付回调、主动查单、手动校验三条链路的幂等性，确保不会重复发放会员。
- [ ] 下单时写入商品快照：商品名、价格、时长、`plan_code`，避免后续改价导致旧订单显示错乱。
- [ ] 支付成功后，前端显示成功态卡片或横幅，并明确展示会员等级与到期时间。
- [ ] 支付失败、通道关闭、网络异常等错误文案统一转成人能看懂的提示。

## Phase 3：后台运营能力

- [ ] admin 订单列表支持按状态筛选：待支付、已支付、已关闭、已退款。
- [ ] admin 订单列表支持按用户搜索。
- [ ] admin 增加“重新发放会员”按钮，用于补单或异常修复。
- [ ] 记录价格修改、手工补单、套餐变更等关键操作审计日志。

## Phase 4：前端购买体验

- [ ] 在 `Pro / Pro Max` 套餐卡片中直接展示权益差异，减少用户理解成本。
- [ ] 支付成功后自动关闭旧二维码展示，避免界面继续停留在“待付款”视觉状态。

## 执行规则

- 每完成一项，优先本地验证。
- 每个可独立验收的阶段都允许单独提交。
- 提交后同步到远端仓库。
- 涉及 `CLIProxyCloud` 的变更，在确认后同步服务器。
- 所有功能以“人工审核后继续下一项”为默认节奏。

## 当前优先顺序

1. 复用未支付订单
2. 订单倒计时
3. “我已支付，立即校验”
4. 支付成功成功态
5. 商品快照
